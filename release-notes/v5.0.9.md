## What's Changed

### Security

- **Fixed SQL injection in the location and layer query templates.**
  Any user with access to a layer could send request values which were written into the SQL string instead of being passed to the database as query parameters, and run SQL with the privileges of the layer's database connection. This affected the `location_update`, `location_new`, `layer_extent` and `sql_table_insert` templates and the `viewport` param of layer queries. Body values of these templates are now always passed as query parameters, and field names and casts must be SQL identifiers, otherwise the request fails with `400`; `sql_table_insert` skips such keys, including keys with a `-` which were accepted before. Body keys can no longer overwrite template params such as `table`. The `viewport` bounds must be numbers and its SRID an integer. The `id` field and the layer `qID` can't be updated in any letter case. Upgrade to v5.0.9; until then, restrict the database role of layer connections to the required tables and privileges. See the advisory [GHSA-fr3m-gfpv-3cmv](https://github.com/GEOLYTIX/xyz/security/advisories/GHSA-fr3m-gfpv-3cmv). Thanks @dbauszus-glx!

- **String values with quotes are stored as entered.**
  Saving a location field with a single quote stored the quote twice, so `O'Brien's` was saved as `O''Brien''s`. Values are no longer escaped before they are passed as query parameters. Thanks @dbauszus-glx! [#3029](https://github.com/GEOLYTIX/xyz/issues/3029)

### Location Fixes

- **Removing a location no longer throws while its layer entry loads.**
  A location with a `type: layer` entry which was removed while the entry layer was still reloading, or while a `wkth3` feature format was loading, threw `Cannot read properties of undefined (reading 'setSource')` or `(reading 'getSource')`. Removing the location now cancels the pending reload, and a late response for the removed layer is discarded. Thanks @dbauszus-glx! [#3054](https://github.com/GEOLYTIX/xyz/pull/3054)

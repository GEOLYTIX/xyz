## What's Changed

### SAML Fixes

- **SAML assertions, logout and metadata are validated and answered correctly.**
  `SAML_ACCEPTED_CLOCK_SKEW` defaulted to `-1`, which turned off the `NotBefore` and `NotOnOrAfter` checks. An expired or captured SAML response was accepted at the ACS indefinitely. The skew is now parsed as an integer number of milliseconds and defaults to `60000`. Negative and non-integer values log a warning and use the default, so the checks can no longer be turned off.

  `/saml/logout` read the user cookie without checking its signature, so a forged cookie got a LogoutRequest signed with the SP key. The cookie signature is now verified, and an expired cookie with a valid signature still ends the IdP session. A cookie without `nameID` and `sessionIndex`, or with an invalid signature, only logs the user out locally. The user cookie is now cleared before the redirect to the IdP, so the local session ends even if the IdP never returns to the logout callback.

  A LogoutRequest sent by the IdP to `/saml/logout/callback` was not answered. A signed LogoutRequest in the Redirect or POST binding is now answered with a LogoutResponse redirect to the IdP. An unsigned or invalid request only clears the user cookie.

  An invalid SAML response at the ACS was only logged, and the request stayed open until the function timed out. A rejected response, or a response without a `nameID`, now gets a `401`. An error in the ACL lookup gets a `500`. The `redirect` and `lookup` values are no longer signed into the user token for any login method.

  `/saml/metadata` published the IdP certificate as the SP signing certificate. It now publishes the SP certificate from `SAML_SP_CRT`.

  **Check before upgrading:**
  - The ACS now returns a `401` for an assertion outside its `NotBefore`/`NotOnOrAfter` validity window plus the `SAML_ACCEPTED_CLOCK_SKEW` tolerance (60 seconds by default). A server whose clock is out of step with the IdP by more than that tolerance can have valid logins rejected.
  - IdP-initiated logout now ends at the IdP's SLO URL instead of `DIR`. Without `SAML_SP_CRT`, the LogoutResponse is unsigned, and some IdPs (for example ADFS or Entra ID) reject unsigned responses.
  - An IdP that imported the old metadata has the IdP certificate registered as the SP signing certificate. Import the metadata again.
  - `@node-saml/node-saml` now requires `^5.2.0`. The `SAML_SP_CRT` `.crt` file must hold exactly one X.509 certificate, not a bare public key or a certificate chain.

  Thanks @dbauszus-glx! [#3075](https://github.com/GEOLYTIX/xyz/pull/3075)

- **SAML deployments read their certificates from the right folder and check their configuration on startup.**
  The SAML app reads its certificates from `apps/saml`, but `apps/saml/vercel.json`, the SAML README and `DEPLOYMENT.md` shipped `apps/xyz/*.crt` and `apps/xyz/*.pem`. A Vercel SAML deployment set up as documented had no certificates it could read. The configuration and docs now ship `apps/saml/*.crt` and `apps/saml/*.pem`. `apps/xyz/*.pem` is still shipped for a `SECRET_KEY` file kept there.

  A missing `SAML_*` variable or certificate file only showed up as an error on the first login. The SAML server now checks its configuration on startup and does not start if `SAML_ACS`, `SAML_ENTITY_ID`, `SAML_IDP_CRT` or `SAML_SSO` is missing, if a certificate file can't be read, if the `SAML_SP_CRT` private key cannot be parsed, or if the `SAML_SP_CRT` certificate is not a single X.509 certificate matching its private key. The error names the variable or file.

  Refreshing the user cookie kept only the SAML `nameID` and `sessionIndex`. A logout after a refresh sent the IdP a LogoutRequest without the NameID format and qualifiers, which some IdPs reject, so the IdP session stayed open. The refreshed cookie now keeps `nameIDFormat`, `nameQualifier` and `spNameQualifier` as well.

  The ACL connection pool had no error listener. When the database closed an idle connection, the error was uncaught and ended the process. It is now logged, as it already was for the workspace connections.

  **Check before upgrading:**
  - Move the gitignored `SAML_IDP_CRT` and `SAML_SP_CRT` certificate and key files from `apps/xyz/` to `apps/saml/`.

  Thanks @dbauszus-glx! [#3093](https://github.com/GEOLYTIX/xyz/pull/3093)

### Location Fixes

- **Entry tooltips stay on the location view after it renders again.**
  An infoj entry with a `tooltip` showed its tooltip icon only on the first render of the location view. Saving the location, toggling edit mode or editing a geometry renders the view again with new entry labels, and the icon was left on the old label, so it disappeared. The tooltip icon is now moved to the new label on every render. Thanks @simon-leech! [#3094](https://github.com/GEOLYTIX/xyz/pull/3094)

### Maintenance

- **Resolved SonarCloud issues in the workspace templates.**
  The query parameter changes in v5.0.9 raised SonarCloud issues in the `location_new`, `location_update`, `sql_table_insert` and `layer_extent` templates. The templates were refactored to resolve them. The generated SQL, accepted field names and error responses are unchanged. Thanks @dbauszus-glx! [#3077](https://github.com/GEOLYTIX/xyz/pull/3077)

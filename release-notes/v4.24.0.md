## What's Changed

### Templates and Workspace

- **Objects in arrays [eg. Infoj entries] can now declare their own role-scoped templates.**
  Only layers and locales could combine `templates` with role-based merging, using dot notation to combine a template's role with its parent (for example `stores.foo`). Individual `infoj` entries had no equivalent, so template-driven role composition was unavailable at the entry level. Entries can now declare a `templates` array, and the combined role must be held by the user before the template's properties are merged in. @dbauszus-glx [#2883](https://github.com/GEOLYTIX/xyz/pull/2883)

- **Fixed workspace cache refreshes corrupting in-flight requests, and reduced duplicate template fetching.**
  The workspace was held in module scope and reassigned on every `composeObj` call, so a request already in progress when the cache refreshed (or when `workspaceCache(true)` was called) could read or write a workspace object other requests were no longer using. The workspace is now threaded through as a parameter instead of shared module state, and template sources are cached in a `src` map to avoid refetching the same template and to guard against circular references. @dbauszus-glx [#2883](https://github.com/GEOLYTIX/xyz/pull/2883)

- **Removed the negated roles option from workspace merging.**
  Negated `roles` values in `objMerge` were not filtering as intended and added complexity with no practical use case alongside `template.role` and nested roles. Negated roles are no longer supported; role filtering now uses a simpler pass over `clone.roles`. @dbauszus-glx [#2865](https://github.com/GEOLYTIX/xyz/pull/2865)

- **Improved test coverage**
  The _workspace, cache, composeObj, getLayer, getLocale, and getTemplate modules have now over 97% test coverage. @dbauszus-glx [#2883](https://github.com/GEOLYTIX/xyz/pull/2883)

### Query Fixes

- **Fixed hover and infotip queries losing layer-specific query parameters.**
  Requests for hover and infotip content did not include `layer.queryparams`, so templates could not access layer-specific parameters. These are now spread into the query params before building the request, making them available to hover/infotip templates. @cityremade [#2914](https://github.com/GEOLYTIX/xyz/pull/2914)

- **Prevented query templates from leaking database connections across layers.**
  A shared template object was mutated when a layer's database connection was assigned to it, so a later layer reusing the same template would incorrectly inherit the first layer's connection. The query module now copies the template before assigning a connection, prioritizing layer, then workspace, then template database settings. @simon-leech [#2806](https://github.com/GEOLYTIX/xyz/pull/2806)

### Entry Fixes

- **Stopped `entry.options` from resetting while typing.**
  Entry options were cleared on every `keyup`, even for entries meant to populate their options from a query as the user types. A new `edit.dynamic` flag now controls this behavior, keeping options empty until populated by the query instead of being reset automatically. @dbauszus-glx [#2814](https://github.com/GEOLYTIX/xyz/pull/2814)

### Location View and CSS Fixes

- **Fixed group padding in location views.**
  Container padding for groups within a location view was forced to `0`, overriding the surrounding layout. Group containers and their grid gap now inherit padding from the parent location view container, matching the rest of the layout. @cityremade [#2911](https://github.com/GEOLYTIX/xyz/pull/2911)

- **Refined layer view styling and dark mode contrast.**
  Layer view drawers and location view containers used inconsistent colors and selectors. Drawer colors now follow a consistent base, secondary, and tertiary hierarchy, expanded drawers use a flat bordered look, collapsed drawers show a box shadow to indicate inner content, and dark mode secondary/tertiary colors were swapped for better contrast. @cityremade [#2697](https://github.com/GEOLYTIX/xyz/pull/2697)

### Security

- **Reduced sensitive data exposure in application logs.**
  Logging previously captured raw request bodies and URLs, including a `mailer_body` key and a `view-req-url` key that could contain user-controlled data. The mailer logger now reads the recipient email from the user object, fetch logging captures the response URL and status instead of the request URL, and the request-body and request-URL logger keys were removed. @dbauszus-glx [#2820](https://github.com/GEOLYTIX/xyz/pull/2820)

- **Removed user-controlled data from database error logging.**
  Database pool errors were passed to the logger's `err` condition, which could expose user-controlled values through `log.error`. These errors are now written directly to standard output instead of routed through the logger. @dbauszus-glx [#2817](https://github.com/GEOLYTIX/xyz/pull/2817)

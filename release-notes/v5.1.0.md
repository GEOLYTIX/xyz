## Already Merged

### MAPP Library Package

- **The MAPP library is now published to npm as `@geolytix/mapp`.**
  Pages outside XYZ can install the library with `npm install @geolytix/mapp` (or `@next` for release candidates), import it with `import mapp from '@geolytix/mapp'`, and load the styles from `@geolytix/mapp/css`. The package can also be loaded from the jsDelivr CDN. `ol` is a peer dependency and must be available as the `ol` global, and pages outside XYZ set `mapp.host`. The npm version always matches the XYZ release version. The XYZ views keep loading `public/js/lib/mapp.js` and `public/css/mapp.css` as before. The Openlayers version check also used `parseFloat`, so `ol` 10.11 was treated as older than 10.8; the versions are now compared correctly. Thanks @dbauszus-glx! [#3053](https://github.com/GEOLYTIX/xyz/pull/3053)

- **The MAPP.UI library moved into its own app.**
  The ui library moved from `apps/mapp/lib/ui` into `apps/ui` as `@geolytix/mapp-ui`. Views, templates and the built `public/js/lib/{mapp,ui}.js` and `public/css/{mapp,ui}.css` paths are unchanged, so map users and locale authors are not affected. `mapp.js` must still load before `ui.js`, because the ui uses the `mapp` global. A CI check now fails if the mapp library references `mapp.ui`. Contributors may need to delete a stale `chunk-*.js` file from a local `public/js/lib`. Thanks @dbauszus-glx! [#3023](https://github.com/GEOLYTIX/xyz/pull/3023)

### API Access

- **Added `CORS_ORIGINS` for cross-origin API access.**
  Pages on other sites could not call the XYZ API or load `mapp.js` from `/public`. The new `CORS_ORIGINS` environment variable takes a comma-separated list of origins, or `*`. A listed origin is echoed in `Access-Control-Allow-Origin`, `*` allows every origin, and preflight requests from an allowed origin are answered. Other origins get no CORS headers. Credentials are never allowed: the session cookie is not sent cross-origin, so such requests are anonymous unless they pass a token. This suits public instances. Nothing changes when `CORS_ORIGINS` is not set. Thanks @dbauszus-glx! [#3129](https://github.com/GEOLYTIX/xyz/pull/3129)

### Location Fixes

- **Edits made while a location update is pending are no longer lost.**
  `location.update()` saved every current `newValue` as `entry.value` when the request returned, including values edited while the request was pending, for example while a plugin saved an isoline. Those edits were never sent, but the view showed them as saved, and reopening the location showed the old value. Overlapping updates could also finish out of order and overwrite a newer value. Only the values that were sent are now marked as saved, and later edits stay as unsaved changes. Updates on the same location run one after another in call order, and a failed update does not block later ones. Thanks @dbauszus-glx! [#3069](https://github.com/GEOLYTIX/xyz/pull/3069)

- **New locations now appear on MVT layers after a reload.**
  After `layer.reload()`, for example after creating a location, a map move could supersede the properties load that was meant to refresh the tiles. The new feature then got its properties but was not drawn. The reload now stays pending until the first successful `wkt_properties` response, which refreshes the tiles when it contains a new feature. The `wkt_properties` format also read an `id` field listed in `fields` from the wrong column, and feature properties could overwrite the tile feature `id`. Both are fixed. Distributed themes now remove the values of features that left the layer, so stale categories no longer stay in the theme and its legend, and a returning feature gets its previous colour back. Thanks @dbauszus-glx! [#3079](https://github.com/GEOLYTIX/xyz/pull/3079)

### Layer Order Changes

- **Layers not listed in `layer_order` are now drawn on top.**
  The `layer_order` plugin sorted layers whose keys are not listed in the locale's `layer_order` to the start of the `locale.layers` array, so they were drawn below the listed layers, contrary to the plugin documentation. A locale without `layers` also threw when the plugin ran. Unlisted layers now move to the end of the array in their original order and are drawn on top. Listed layers keep the same order as before. Review the `layer_order` of your locales: if a locale relied on unlisted layers being drawn at the bottom, add those layer keys to `layer_order`. Thanks @dbauszus-glx! [#3084](https://github.com/GEOLYTIX/xyz/pull/3084)

### Drawing Fixes

- **Fixed the vertex removal, `srid` and snap bugs in the map interactions.**
  The draw and modify interactions always requested features with `EPSG:undefined`, so the `srid` param was ignored. "Remove vertex" was offered on triangles and on holes or multipolygon parts that could not lose a vertex. Deleting the last part of a multipolygon threw. Removing a snap interaction read the wrong layer source. These now work as expected. Thanks @dbauszus-glx! [#3087](https://github.com/GEOLYTIX/xyz/pull/3087)

### MAPP Library Fixes

- **Fixed formatting, theming and geometry bugs found by the new MAPP library tests.**
  `numericFormatter` ignored `round: 0`, `hexa` did not pad single-digit alpha values, `temporal` formatted an invalid date as today, `merge` dropped nested objects when the target value was a primitive, and `polygonIntersectFeatures` never matched points. Graduated themes without categories now log a warning instead of throwing, distributed themes handle features without a value, default fields are no longer duplicated, and a failed location insert is caught. `mapp.utils.convert` now loads its library through `esmImport`, and a failed import leaves the value unconverted and labelled with its source units. The legacy `test` plugin was removed from `mapp.plugins`. Thanks @dbauszus-glx! [#3026](https://github.com/GEOLYTIX/xyz/pull/3026)

- **Fixed the CSV upload, CSV download, user locale and IndexedDB utilities.**
  `csvUpload` uploaded `0` as `null` in `int` and `numeric` columns. `csvDownload` always joined the header row with a comma, whatever the `separator`. The `userLocale` methods threw when no user was logged in. `userIndexedDB` never resolved when opening a new store in an existing database, and its `add` method could not add a record. All of these now work as documented. Thanks @dbauszus-glx! [#3082](https://github.com/GEOLYTIX/xyz/pull/3082)

- **A CSV file that cannot be read now reports an error.**
  `csvUpload` read files with `FileReader` and had no error handler, so an unreadable file left the upload waiting without any message. A failed read now returns `[error]`, like the parse and chunk failures, and the upload shows its error alert. UTF-16 files with a byte order mark still upload as before. Thanks @dbauszus-glx! [#3100](https://github.com/GEOLYTIX/xyz/pull/3100)

- **Any key press now resets the idle logout timer.**
  `idleLogout` listened for the deprecated `keypress` event, so arrow keys, Escape and other non-character keys did not count as activity. It also replaced any `window.onload`, `window.onclick` and other `window.on*` handlers set by plugins. It now listens for `keydown` with `addEventListener` and leaves existing handlers alone. Thanks @dbauszus-glx! [#3081](https://github.com/GEOLYTIX/xyz/pull/3081)

Test files then got a different module instance than the `mapp` global, and identity checks failed. The Vitest `root` now uses an uppercase drive letter. Nothing changes on Linux, macOS or CI. Thanks @dbauszus-glx! [#3149](https://github.com/GEOLYTIX/xyz/pull/3149)

## Still to Be Merged

### Filter Fixes

- **Numeric and integer filters no longer fail silently when the min/max query fails.**
  `generateMinMax` read `response.minmax` without checking the response. When the `field_minmax` query failed (for example a 400 at a zoom level where `layer.tables` has a `null` entry, or a 500 from a SQL error), choosing a numeric or integer filter threw a `TypeError`, and no filter card appeared. A failed or empty response now logs a warning, and the filter shows the no data message. The query now uses the layer's first non-null table when the current zoom has no table, like `filter_in` does. An integer filter on a field with only `null` values now shows the no data message instead of a slider fixed at 0. The documented `filter.minmax_query` key now replaces the default `field_minmax` template. Thanks @Yshuro! [#3151](https://github.com/GEOLYTIX/xyz/pull/3151)

### Testing and Maintenance

- **The ui tests wait for the library promises instead of polling.**
  On Windows the testhost can stall for several seconds when an HTTP socket closes, so the 5s polls in the filter, histogram and distributed legend tests timed out. These tests now wait for the lib method or request they depend on. Thanks @dbauszus-glx! [#3150](https://github.com/GEOLYTIX/xyz/pull/3150)

- **Added maplibre format tests.**
  The maplibre layer format is tested with devdb tiles, and with the Mapbox API when a `MAPBOX_ACCESS_TOKEN` is available. Thanks @dbauszus-glx! [#3101](https://github.com/GEOLYTIX/xyz/pull/3101)

### Documentation

- **The documentation moved from the GitHub Wiki into a `knowledge/` bundle in the repository.**
  The Wiki lived in a separate repository that pull requests and CI never touched, so it drifted from the code. Some environment variables, such as `TRUSTED_RETURN_HOSTS`, the `JWT_*` and the `OTEL_*` variables, were on no Wiki page. All Wiki pages are now migrated into Open Knowledge Format concepts under `knowledge/`, covering the architecture, environment variables, workspace keys, security, views and deployment. `SETUP.md` and `DEPLOYMENT.md` now point into the bundle. The Wiki will be generated from the bundle for each release and must not be edited by hand. `pnpm knowledge:check` and a new CI workflow validate the concepts, and a new environment variable without a concept fails the check. Thanks @dbauszus-glx! [#3088](https://github.com/GEOLYTIX/xyz/pull/3088)

## What's Changed

### Monorepo And Application Split

- **XYZ is now a pnpm and Turborepo monorepo split into separate applications.**
  Everything previously lived in one flat package: the frontend in `lib/`, the backend in `api/` and `mod/`, and a single root `express.js` entry point. The repository is now a pnpm workspace driven by `turbo.json`, split into `@geolytix/mapp` (`apps/mapp`), `@geolytix/xyz-app` (`apps/xyz`), and `@geolytix/xyz-saml-app` (`apps/saml`), with a thin root server composing them. SAML is no longer built into the API module — a fork wires its routes explicitly — and every import path has moved. Forks and deployments must migrate to pnpm workspaces and update their entry points. Thanks @dbauszus-glx! [#2744](https://github.com/GEOLYTIX/xyz/pull/2744)

- **The SAML application now ships its own server and dependencies.**
  SAML ran from the repository root `server.js`, and `@node-saml/node-saml` was an optional dependency of the XYZ app, so SAML packages were deployed alongside every XYZ server. The root `server.js` is gone; SAML runs from `apps/saml/server.js` with its own `vercel.json`, started with `pnpm dev:saml`, and `@node-saml/node-saml` was removed from `apps/xyz`. Thanks @dbauszus-glx! [#2763](https://github.com/GEOLYTIX/xyz/pull/2763)

- **Dependency versions are now declared once in a pnpm catalog, and the monorepo carries a single version number.**
  Each app pinned its own third-party versions, so `express` and `express-rate-limit` could drift between `apps/auth`, `apps/saml`, and `apps/xyz`, and the four packages reported four different versions (root `v5.0.0`, `@geolytix/xyz-app` and `@geolytix/mapp` at `v4.22.1`, `@geolytix/xyz-saml-app` at `v1.0.0`). All third-party dependencies now resolve through the `catalog:` section of `pnpm-workspace.yaml`, local packages use `workspace:*` instead of `file:` paths, and the `version` field was removed from every app manifest so the root `package.json` is the single source of truth. This requires pnpm 11. Thanks @RobAndrewHurst! [#2827](https://github.com/GEOLYTIX/xyz/pull/2827)

- **Express dependencies are declared once at the monorepo root.**
  `express`, `express-rate-limit`, and `dotenv` were declared as runtime dependencies of `@geolytix/xyz-app` while also appearing as root `devDependencies` at different versions (`^5.1.0` versus `5.2.0`, `^7.5.0` versus `^7.5.1`), risking duplicate installs. The per-app copies were removed and `express` `5.2.0` and `express-rate-limit` `^7.5.1` moved into the root `dependencies` where they belong. Thanks @RobAndrewHurst! [#2781](https://github.com/GEOLYTIX/xyz/pull/2781)

- **Built MAPP library files are now committed to the repository.**
  `public/js/lib/mapp.js` and `public/js/lib/ui.js` were ignored by git and only existed after a local build, so a fresh clone had no library bundles. v5 allows the XYZ server to be deployed without a build step, so the bundles and their source maps now ship in the repository and a clone is deployable as-is. The `.gitignore` rules covering `public/js`, `public/workspaces`, root-level JSON files, and `.pem`/`.crt` files were removed as part of this. Thanks @dbauszus-glx! [#2783](https://github.com/GEOLYTIX/xyz/pull/2783)

### Express Router And Middleware

- **Request handling is now an Express router with composable middleware.**
  Every request entered a single `apps/xyz/api.js` handler that performed the `DIR` redirect, parameter validation, and authentication before dispatching through a hand-rolled `requestRouter`. `api.js` and `requestRouter` are gone, replaced by `createRouter(middleWare)` in `apps/xyz/router.js`, which applies rate limiting, `cookie-parser`, and static assets, then mounts each endpoint as its own Express route. Validation and authorization moved into `rootRedirect`, `validateRequestParams`, and `validateRequestAuth` under `apps/xyz/mod/middleware/`, and authentication failures now return `401` from middleware before any endpoint runs. This is breaking: the `./api` and `./extensions` package exports were removed in favour of `./router`, `keyVerification()` no longer exists, `apps/auth/auth.js` became `apps/auth/customAuth.js`, and validated parameters arrive on `req._params`, so endpoint modules must call `Object.assign(req.params, req._params)` themselves. Thanks @dbauszus-glx! [#2784](https://github.com/GEOLYTIX/xyz/pull/2784)

- **The `file:` provider now resolves relative paths from the process working directory.**
  Paths were resolved relative to the provider module's own location, so after the monorepo restructure existing launch configurations needed absurd `../../../../` prefixes to reach the same files. `apps/xyz/mod/provider/file.js` now joins against `process.cwd()`, and the view templates dropped their `../../` prefixes — `file:../../public/views/_default.html` becomes `file:/public/views/_default.html`. Workspace and launch configurations holding `file:` references must be updated to the new reference point. Thanks @dbauszus-glx! [#2775](https://github.com/GEOLYTIX/xyz/pull/2775)

### Authentication And Session Security

- **Added a template application for custom authentication providers, with a single `AUTH_PATH` variable driving login and logout routes.**
  The request-auth redirect contained a SAML-specific branch, and SAML and the built-in login each signed their own cookies and performed their own ACL lookups, so there was no reusable path for a non-SAML provider. A new `apps/auth` workspace serves `/custom/login`, `/custom/verify`, and `/custom/logout` as a working template, and the optional `AUTH_PATH` environment variable now drives the login redirect server-side and the login and logout links client-side through `params.authPath`. A shared `apps/xyz/mod/user/redirect.js` handles the ACL lookup, JWT cookie signing, and redirect cookie for every provider, and a new `api/user/logout` route was added. `apps/xyz/mod/utils/redirect.js` and its `setRedirect` export were removed, and `@node-saml/node-saml` became a hard dependency of `apps/saml`. Thanks @dbauszus-glx! [#2790](https://github.com/GEOLYTIX/xyz/pull/2790)

- **Cookie attributes are now set once through `COOKIE_PROPS`, and cookies are destroyed consistently.**
  Every `Set-Cookie` call site wrote its own attribute string, so some cookies shipped without `SameSite` or `Secure`, `Secure` was skipped whenever the request host contained `localhost`, and revocation was inconsistent — the XYZ modules used `Max-Age=0` while the SAML logout callback used an `Expires` date in 1970 with attributes that did not match the cookie it was clearing. A new `COOKIE_PROPS` variable defaults to `Secure; HttpOnly; SameSite=Strict; Path=${DIR}` and is interpolated into every cookie across `apps/xyz`, `apps/auth`, and `apps/saml`, and all revocation paths now use `NAME=null; Max-Age=0` with the same attributes so browsers accept the removal. SAML logins also fall back to the `RelayState` value from the POST body or query when the strictly same-site `_redirect` cookie is not delivered on the cross-site IdP POST, so the user lands on their intended page. Developers serving XYZ over plain HTTP must now set `COOKIE_PROPS` explicitly to drop `Secure`. Thanks @dbauszus-glx! [#2862](https://github.com/GEOLYTIX/xyz/pull/2862)

### Workspace Authorization

- **Workspace scope logic is now reachable outside the workspace API.**
  `checkScope` was module-private inside `composeObj.js`, so authorization layers had to reimplement scope matching and drifted from the canonical semantics, and scope enumeration existed only as an inline `scopes()` request handler, so obtaining the full scope universe required an HTTP call. A new `apps/xyz/mod/workspace/scopes.js` exports `checkScope`, `getScopes`, `scopesArray`, and `scopesTree` as reusable functions, with `scopesArray` and `scopesTree` now pure transforms rather than functions writing to the response. The `scopes()` endpoint responses are unchanged. Thanks @RobAndrewHurst! [#2920](https://github.com/GEOLYTIX/xyz/pull/2920)

- **Workspace composition can now delegate scope checks to a per-user authorization provider.**
  Access decisions ran through a synchronous `checkScope` against the roles array in the user's token, with no seam for substitution. Hosts authorizing against external policy stores such as OpenFGA, OPA, or Cerbos therefore reimplemented much of the workspace API in a shim, composing twice per request and failing open whenever route interception missed a path. A new `apps/xyz/mod/workspace/authorization.js` holds a keyed registry — `setAuthorizationProvider(key, provider)`, and `authorizeScope(context)` awaiting the provider's `checkScope` — wired into both `composeObj` and `mergeTemplateIntoObj` so denied template content never reaches the composed object. A missing provider, a non-`true` return, or a thrown error all deny, and behavior is unchanged for users with no provider. The provider is selected per user through `user.authorization_provider` rather than a global flag, so several providers can coexist; the whole user object is now threaded through composition instead of just the roles array, and a provider user bypasses the `accessRoles` gate so the provider alone decides. Because the property is assigned by the composing host and not stored in the ACL, it is now carried across cookie refresh and `api_user` key signing. Breaking for hosts: `composeObj` takes a user object as its second argument rather than a roles array, and `AuthorizationContext.roles` became `AuthorizationContext.user`. Thanks @RobAndrewHurst and @dbauszus-glx! [#2925](https://github.com/GEOLYTIX/xyz/pull/2925) [#2930](https://github.com/GEOLYTIX/xyz/pull/2930)

### Environment And Deployment

- **MAPP now builds with Vite, and configuration is managed by Varlock instead of `dotenv`.**
  Secrets lived in a plaintext `.env` file with no schema, no typing, and no protection against being printed to a log or committed to git, and the MAPP bundles were built by a bespoke esbuild config with CSS sources under `public/css`. `apps/mapp` now builds through `vite.config.mjs` and `vite.css.config.mjs` with CSS sources and fonts co-located in `apps/mapp/css`, and configuration is declared in a `.env.schema` loaded by Varlock, which types and validates every key and redacts sensitive values from logs and HTTP responses. Google Secret Manager values can be referenced with `gsm()`. Local setup now needs both `.env` and `.env.schema` copied from `varlock/`, and any key not declared in the schema is unavailable. For Vercel, `pnpm freeze-env` and `pnpm deploy:vercel` produce an encrypted `.varlock.blob` that ships with the deployment, so serverless invocations make no Secret Manager calls. Environment defaults switched from `??=` to `||=` because Varlock injects declared-but-empty keys as empty strings. Thanks @RobAndrewHurst! [#2869](https://github.com/GEOLYTIX/xyz/pull/2869)

- **Varlock is now optional at runtime, and a failed workspace load is retried.**
  Deploying to Vercel without a `.varlock.blob` crashed at boot, so the frozen-environment flow was mandatory even for deployments happy to use Vercel project environment variables. Blob hydration is now conditional and Varlock initialises with `allowFail`, so the process falls back to the environment it was started with; an encrypted blob present without `_VARLOCK_ENV_KEY` still throws, since that is a misconfiguration rather than an opt-out. Running without a blob does mean losing schema validation, `gsm()` references, and blob-driven redaction. Separately, when `getSrc` failed to load the workspace the failure stayed cached forever and was never retried; `workspacePromise` is now reset so the next request tries again. This release also adds `DEPLOYMENT.md` covering Vercel and self-hosted Node deployment, the frozen blob flow, Google Secret Manager, and troubleshooting. Thanks @RobAndrewHurst! [#2912](https://github.com/GEOLYTIX/xyz/pull/2912)

### Documentation

- **Added a setup guide covering clone to first run, and gave each application its own README.**
  There was no single walkthrough from clone to a running instance: `README.md` still advertised v4.23.1 and a monolithic Express layout, and a long `DEVELOPING.md` mixed build, debug, and app-specific detail. A new `SETUP.md` covers repository contents, prerequisites, install, the VSCode `launch.json`, environment variables, first-run expectations, build commands, Vercel deployment, tests, database-backed setups, SAML, and troubleshooting. New `apps/mapp/README.md` and `apps/saml/README.md` carry app-specific commands and routes, `apps/xyz/README.md` was corrected, and `DEVELOPING.md` is now a short contributor-tooling page pointing at them. The root `pnpm dev` script now starts the XYZ app rather than the SAML dev server. Thanks @RobAndrewHurst! [#2786](https://github.com/GEOLYTIX/xyz/pull/2786)

### Testing And Tooling

- **The Vitest configuration moved to the repository root so editor extensions discover the tests.**
  The config lived at `apps/xyz/vitest.config.mjs`, where the VSCode Vitest extension could not pick it up. A root `vitest.config.mjs` now points at the `apps/xyz` test directories and setup file, the test dependencies moved to the root `package.json`, `apps/xyz/tests` was added to `.vercelignore` so tests are not uploaded, and `apps/xyz/vercel.json` was added for the Node runtime entry point. Thanks @dbauszus-glx! [#2767](https://github.com/GEOLYTIX/xyz/pull/2767)

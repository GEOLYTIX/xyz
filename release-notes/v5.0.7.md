## What's Changed

### Login Fixes

- **The password reset link opens the password reset form again.**
  Since the v5 Express middleware refactor, `/api/user/register` no longer copied query parameters into `req.params`. Clicking "forgot password", or opening a reset link, ignored `?reset=true` and showed the registration form on every v5 instance. The register route now reads `reset` from the query string when it is not already set, so `?reset=true` loads `password_reset_view` again. Thanks @simon-leech! [#2982](https://github.com/GEOLYTIX/xyz/pull/2982)

- **SAML logins no longer loop between the app and the identity provider.**
  Since SAML moved to the shared redirect helper, the user cookie set at `/saml/acs` used the default `SameSite=Strict` `COOKIE_PROPS`. The IdP posts the SAML response cross-site, and the following 302 redirect stayed in that cross-site navigation. The browser did not send the cookie, so the user went back to login and looped for as long as the IdP session lasted.

  The ACS now answers a successful login with a `200` HTML page that redirects with a meta refresh and a "Continue" link. The browser follows it as a same-site navigation and sends the cookie, so `COOKIE_PROPS` stays `Strict`. The redirect location, which can come from `RelayState`, is HTML-escaped. Errors such as an unknown user still return their own status.

  `SAML_LOGIN` was removed in v5.0.0 and is ignored. `PRIVATE` SAML instances that still set it sent users to `/api/user/login` instead of the SSO login. Set `AUTH_PATH=/saml` instead. `SETUP.md` and `apps/saml/README.md` now describe the migration. Thanks @simon-leech! [#2986](https://github.com/GEOLYTIX/xyz/pull/2986)

### Legend and Theme Fixes

- **`filterOnly` themes now hide features from cluster layers.**
  A categorized or graduated theme with `filterOnly: true` hides a toggled-off category by setting its style to `null`. On layers with `cluster.distance`, the cluster source still clustered the hidden features. Clusters made only of hidden features were still drawn. A cluster with one visible feature still rendered as a cluster. Counts, `max_size` and the cluster popup included hidden features, and toggling a legend category did not re-cluster.

  The cluster source now skips any feature that the layer style would not display. Toggling a category on a clustered `filterOnly` layer re-clusters without reloading data. A cluster with one visible feature now renders as a single themed location.

  Categorized themes on several `theme.fields` now hide a feature when any of its matching categories is toggled off; previously it was drawn with the icons from its other fields. Removing a category filter on a query-filtered theme no longer throws for categories with `keys`, no longer removes an unrelated value when the value is missing, and drops the field filter once it is empty.

  For plugin authors: `featureStyle.mjs` now has a named `featureStyle` export instead of a default export. The shared feature check is exposed as `mapp.layer.featureProperties`. Thanks @dbauszus-glx! [#2985](https://github.com/GEOLYTIX/xyz/pull/2985)

- **Categorized and graduated legends always return a legend element.**
  Since v5.0.6, `mapp.ui.layers.legends.categorized` and `graduated` returned `undefined` when the layer data had not yet been processed. Custom views and plugins that insert the returned legend into the page showed the text "undefined", typically on first load. Both methods now return `layer.style.legend`: an empty `div.legend` placeholder, or the existing legend. The element is filled once the data arrives. Thanks @simon-leech! [#2980](https://github.com/GEOLYTIX/xyz/pull/2980)

### Map and Location Fixes

- **A failed module import or plugin error no longer stops the map from loading.**
  `mapp.utils.esmImport` never rejected. When esm.sh or a module could not be reached, the promise never settled, and everything awaiting it hung, including mapview initialisation. A plugin that threw also rejected the mapview initialisation.

  `esmImport` now logs the failure and resolves to an `Error`. The failed import is not cached, so the next call tries again. Features that depend on the module are skipped:
  - `mapp.utils.proj4.addProjection` does not add the projection.
  - `maplibre` layers are not created.
  - `wkth3` layers return no features.
  - `jenks` distributions are not computed.
  - The JSON editor and its dataview are not created.

  Each plugin now runs in its own `try`/`catch`. A failing plugin is logged, and the mapview and the other plugins still load. Custom code that calls `esmImport` should check the result with `instanceof Error`. Thanks @dbauszus-glx! [#2981](https://github.com/GEOLYTIX/xyz/pull/2981)

- **Geometry entries no longer leave orphaned layers on the map.**
  A geometry entry whose `api()` re-renders the location view while its request is pending created a second layer. One example is an `isoline_glx` entry with `dependents` and without `blocking`. The original `show()` call then overwrote `entry.L`, and the first layer stayed on the map, so closing the location left the isoline behind. `show()` now removes any existing layer again right before creating the new one, so each entry keeps one layer that closing the location removes. Thanks @dbauszus-glx! [#2984](https://github.com/GEOLYTIX/xyz/pull/2984)

### API and Server

- **API responses are now marked `Cache-Control: private, no-cache`.**
  The router set no `Cache-Control` header on API responses. The header in `vercel.json` was not applied, and it never covered other hosts. Browsers downloaded large workspace and locale responses in full on every refresh. Nothing stopped shared caches from storing responses that depend on the user and their roles.

  The Express router now sets `Cache-Control: private, no-cache` for everything under `${DIR}/api`, on Vercel and on other hosts. Browsers revalidate with the ETag and get `304 Not Modified` when the response has not changed. Shared caches and CDNs do not store responses. Handlers can still set their own header. Thanks @dbauszus-glx! [#2974](https://github.com/GEOLYTIX/xyz/pull/2974)

- **Added an admin-only `/api/workspace/templates` endpoint.**
  Admins can now get the workspace `templates`, including templates added when locales and layers are composed. Users without admin credentials get `403`. Thanks @dbauszus-glx! [#2976](https://github.com/GEOLYTIX/xyz/pull/2976)

- **Database connections now receive a single `params` object with `res.locals`.**
  Connection functions in the `dbs` module were called with positional arguments `(query, variables, timeout, options)`. A host that replaced a connection could not get per-request context, such as a tenant id, from its own middleware. Connections are now called with `{ query, variables, timeout, nonblocking, locals }`, where `locals` is `res.locals`. `req` is not passed, because clients can write to `req.params` through the query string. The built-in Postgres connections behave as before. Hosts or code that call or replace `dbs` connection functions must switch to the object signature. Thanks @AlexanderGeere! [#2973](https://github.com/GEOLYTIX/xyz/pull/2973)

- **Added optional OpenTelemetry request tracing.**
  Tracing is off unless an exporter is configured through `OTEL_*` environment variables such as `OTEL_EXPORTER_OTLP_ENDPOINT` or `OTEL_TRACES_EXPORTER`. When it is on, each API request gets a root span with nested spans for workspace caching, source requests, workspace composition, and database queries.
  - Spans record timings, cache hits, pool counts, and error codes. They do not record SQL text, query parameters, or source query strings.
  - The SDK and exporter are optional dependencies and are loaded only when tracing is on.
  - Setting `OTEL_TRACES_EXPORTER=console` logs a span tree for each request, and `OTEL_CONSOLE_HTML` writes a local HTML report.
  - The new `pnpm traces` script reads traces from Vercel runtime logs and shows them as terminal waterfalls or an HTML report.

  All variables are documented in `processEnv.js`. Thanks @dbauszus-glx! [#2978](https://github.com/GEOLYTIX/xyz/pull/2978)

### Build, Release and Testing

- **Built MAPP bundles are no longer committed to branches.**
  Every pull request that rebuilt MAPP conflicted on the minified bundles and source maps. `public/js/lib/`, `public/css/mapp.css` and `public/css/ui.css` are now gitignored, so run `pnpm build` after checking out a branch. `pnpm deploy:vercel` builds before deploying. Vercel Git-integration deploys of a branch have no bundles, because `vercel.json` runs no build.

  Merging a version bump into `main` now publishes the release. The release workflow requires `release-notes/<version>.md`, runs the tests, builds MAPP, commits the bundles to the tag only, and creates the GitHub release. Release tags and CDN links to a tag still include the bundles. Turbo now restores the bundles on a cache hit. `RELEASING.md`, `DEPLOYMENT.md` and `SETUP.md` describe the new process. Thanks @dbauszus-glx! [#2979](https://github.com/GEOLYTIX/xyz/pull/2979)

- **Added a local PostGIS database for development and tests.**
  The new `packages/devdb` package runs PostgreSQL with PostGIS in the Node process using PGlite, with seeded example tables, and needs no Docker or native install. `pnpm devdb` starts a persistent database on port 5433 and prints a `DBS_DEV` connection string. The query module tests now run real SQL against an in-memory database instead of a mocked `dbs` module. `packages/devdb` is excluded from Vercel deployments. Thanks @dbauszus-glx! [#2971](https://github.com/GEOLYTIX/xyz/pull/2971)
